FIGURE 02 · TO-BE

目标：一个顶层 MLB 实例编排 L1 / L2，SGLang 保持执行权威

SGLang 仍然决定何时 init、forward、rebalance 和搬权重；MLB 只在这些既有 hook 上被调用。Orchestrator 合并 policy 需求，Adapter 只收集通用 observation 并一次性 materialize；active placement 始终读取 SGLang metadata。

原则 ① 一个顶层 MLB 编排 L1/L2；内部保留 per-layer state
原则 ② LPLB → Waterfill，共享一次通信和一次写回
原则 ③ SGLang 管时序；Orchestrator 管策略组合
结果：M+N M 个框架无关 policy + N 套框架 Adapter + 1 个 Orchestrator；placement 始终以 SGLang metadata 为准。
SGLang：生命周期 / 通信 / 权重 Adapter：框架转换与采集 MoELoadBalancer Orchestrator L1 EPLB policy L2 ordered policy pipeline
顶层结构 一个 MoELoadBalancer 统一编排 L1/L2；算法内部仍可保留模型级与 per-layer state。
调用方向 SGLang 调统一入口；Orchestrator 调 Adapter 收集输入，再调 policies，最后让 Adapter 写回。
状态一致性 MLB L1 只返回 plan；SGLang 搬权重并更新 metadata，L2 Adapter 随后直接读取最新 placement。
